## §0 项目一句话

**Skein** ＝ 一颗常驻屏幕角落的球 + 一套**不预设数量**的叙事骨架。

- **球（提醒载体）**：把"这一期还差哪一段没站住"钉在你眼前，用未完成态做反向监督。
- **工作流（价值本体）**：定主题 → AI 实时推"下一步" → 顺手把素材**喂**进去 → 每段确认够不够 → 你**封顶** → 出草稿 → 跳发布页。

全程真人执行发送，AI 只给建议。产品叙事＝让费曼学习法（以教为学）变成一个工作闭环。

## §2 需求理解（AI 提炼，可能偏差，以 §1 为准）

### 2.1 两条流水线

| 流水线 | 干什么 | 依据 |
|---|---|---|
| **A · 对外**（监测真人回复） | 盯各平台评论/私信/@我 → 提醒 → AI 给回复草稿 → 跳原 APP 真人发送 | P-001 |
| **B · 对内**（任务模式攒素材） | 定主题 → 叙事骨架 → 顺手喂素材 → 确认 → 饱和 → 跳发布页 | P-002 / P-005 / P-010 |

两条流水线共用同一颗球、同一个"奶蛙人设"。

### 2.2 阶段与顺序（v0.5 修正：**原生从悬浮球开始**）

> 旧的「工作流先行、球后置」已被 P-011 推翻。新顺序：球先做，但**球里必须真的连着核心**（球是皮，骨头是下面的数据与规则）。

| 阶段 | 做什么 | 载体 | 出口判据 |
|---|---|---|---|
| **M0** | **球壳 + 探针**：原生置顶小球，三态渲染，可交互面板（PyQt6） | 原生小窗（PyQt6 + Win32） | 显示/点击球后浏览器光标与选区仍在；连续两天愿意开着 |
| **M1** | **最小核心（骨头）**：SQLite + 灵感池 + 立项 + 手工喂 + 覆盖图接真数据 | 同上 | 不靠网页也能走完"立项→喂→够了→封顶" |
| **M2** | **顺手喂**：UIA 读浏览器选区 → 就地选"支撑哪一段" | 采集常驻进程 | 喂一次 ≤2 次操作；浏览器焦点与选区不被破坏 |
| **M3** | **动态任务流**：AI 实时推下一步、结构增删、完成度估算、人封顶 | 接 LLM（本地规则可兜底） | 喂一条后"下一步"与估算确实变化；**界面任何时刻不出现 100%** |
| **M4** | **收口发布**：奶蛙语气草稿 + 跳各平台发布页 | `computer.open_url` 等 | **用一期真主题跑完并真的发出去** |

### 2.4 为悬浮球预留的接入契约（核心与载体解耦）

| 能力 | 说明 |

### 2.5 ★ 叙事骨架 · 动态任务流 · 饱和（本版核心模型）

**结构**

| 层 | 是什么 | 数量 |
|---|---|---|
| **Payoff** | 这一期最想让人记住的那一下 | 1 |
| **节拍 Beat** | 用"必须回答的问题"表述 | **不固定**（AI 实时增删） |
| **素材 Material** | 挂在节拍下的证据（文字/图片/视频/速记） | **不预设，0~N** |

**任务不是提前列好的（P-013）**：立项时 AI 只给**初始理解**（少量几段），随后每收到一条素材就重算「下一步」并允许增删节拍。

**完成度 = 估算值，永远到不了 100%（P-013）**
- 系统只给估算（覆盖 + 支撑强度），**上限钉在 92%**。
- 宣布"完成"的权力永远在人：点「够了，收口」＝封顶，此后不再显示百分比。

**饱和的两条判据**：覆盖（每段至少 1 条）＋ 解释力充分（新素材不再改变这段讲法，且人确认）。依据：质性研究"饱和"——**质量（充分）而非数量（多少）是关键**。

**三方分工**：系统报状态（红/黄/绿 + 冗余提示）｜AI 提缺口、一次只问一个、给估算｜人终裁与封顶。
**铁律：AI 与系统只能提示"还没饱和"，宣布"完成了"的权力永远在人。**

**语汇**：清单项→节拍（提问式）｜`2/4`→覆盖图状态点｜"还差 2 项"→"还有 N 段没站住"｜"可以发了"→"这段讲清了"。

|---|---|
| **Topic** | id · 主题名 · 平台 · 形态 · 目标张数 · **payoff** · **capped**（是否已由人封顶）· 状态 · 创建时间 |
| **Beat** | id · topic_id · seq · **问题表述** · **origin**（ai/human）· locked |

### 2.8 ★ 没有一步是"提前定好"的（v0.6 落地的机制）

P-010 / P-013 要求"任务实时更新、由系统+AI+人一起判断"。落到实现上就是把所有**写死的常量**收进 `app/brain.py` 的六个函数，界面与数据层不动：

| 函数 | 谁在变 | 约束 |
|---|---|---|
| `seed_beats(name, inbox)` | **初始理解**由「期名主体词 + 灵感池里的术语」派生，句式也随期名换档 | 只给 3 段；只注入**一个**术语——列全就又成清单了 |
| `payoff_for(name, mats)` | 这一期最想让人记住的一下，从素材里挑最有"断言感"的一句 | 素材里挑不到就留待定句，不拿别的期凑 |
| `proposals(beats, mbb, unassigned, capped)` | AI 想对结构做的**增/并/撤/收**，一次最多 3 条 | **只提议，不擅自改**；人点"采纳"才落地，"先不用"后不再提 |
| `next_step(...)` | 「下一步」+ 带数字的理由 | 每次喂素材都重算 |
| `estimate(...)` | 完成度估算 | 同一段**边际递减**（第 2 条 +0.17、第 3 条 +0.085…），封顶 92% |
| `draft(...)` | 收口草稿，封面大字取自 payoff | 不再写死某一期的句子 |

**术语提取的边界**：只认 ASCII 技术词（MCP / RAG / Agent…）并按"出现在几份素材里"计数，**不做中文 n-gram**——没有分词器时切出来的是「向量数」「量数据」这类半截词，往问题里注入半截词比不注入更糟。

**落地状态**：`store` 补齐 `update_beat / delete_beat / merge_beats / renumber / set_payoff`；撤下的段其素材退回「未指派」，不丢东西。M3 接 LLM 时**只替换这六个函数的实现**，其余不动。

### 2.9 模型接入（v0.6.2）

`app/llm.py` 是 OpenAI 兼容的适配层（只用标准库）。配置**优先级：环境变量 > 本地配置文件 > 默认值**：

| 来源 | 内容 |
|---|---|
| `%LOCALAPPDATA%\Skein\llm.json` | **主要走这条**：`{"base": "...", "model": "...", "key": "..."}`。放在用户数据目录，**不进代码仓**，不会被误提交 |
| `SKEIN_LLM_BASE / SKEIN_LLM_MODEL / SKEIN_LLM_KEY` | 可选覆盖（给别人用） |
| 默认 | `https://apihub.agnes-ai.com/v1` · `agnes-3.0-flash` |

> 实测（2026-10-10）：`agnes-3.0-flash` 1.8s 可用；TokenPlan 组下 `agnes-3.0-flash-max` / `agnes-2.5-pro` 返回 503「No available channel」，**不要选**。

**两条硬约束**：

1. **失败即静默降级**。模型超时、401、返回非 JSON —— 一律返回 `None`，调用方保留本地规则的结果。**模型掉线时 Skein 仍然是一个能跑完闭环的工具**，只是"没那么懂"。这是红线，不允许出现"没 key 就用不了"。
2. **不在主线程发请求**。统一走后台线程，结果经 `App._cq` 队列回到主线程再碰界面；带**代际计数器**，过期结果直接丢。后台任务覆盖：初始理解重写（只在用户还没动手时替换）、payoff、结构提议、封顶后的口播草稿。

**实测抓到的两个模型坑（都已修）**：

- 结构提议的 prompt 一开始**只给"第 N 段（2 条素材）"这种统计、不给素材原文** → 模型凭空编了一条不存在的素材标题来支撑"这段够了"。`_ctx()` 现在必须带素材原文。
- 模型会在**一段素材都没有**的段上建议"够了"，与"饱和"的定义直接矛盾 → 加了护栏：`lock` 需要该段至少 2 条素材，否则丢弃。

**"懂"到什么程度要说清楚**：标题栏右侧常驻显示当前是「本地规则」/「模型 · xxx」/「**模型不通 · 本地兜底**」，开机做一次不花 token 的连通性探测。配了 key 不等于能用，人不该被含糊的智能感骗。

**验证**：`python llmtest.py` 用桩跑完整链路（JSON 抠取 / 越界与"空段说够了"被丢弃 / 异步落地 / 模型抛异常不影响闭环）；`python uitest.py` 会把 `config.LLM_PATH` 指向临时文件并清掉环境变量，**保证走查既不打网络、也不读你本机的 key**。

### 2.10 ★ 面板是平的，不是流程（v0.7.0 修正）

v0.6.x 的面板把「随手记 → 立项 → 喂素材 → 逐段确认 → 封顶」做成了**五步阶梯**：顶部一条步骤条 + 一张「现在这一步」卡，卡里只显示**当前该用的那一个**控件，其余能力被藏起来。这是错的：

- **素材搜集的组成本来就不固定**。人可能同时在随手记、在喂某一段、在确认另一段。一次只放一个入口，等于强迫人按机器的顺序走。
- 它**违反本项目自己的硬约束**（「核心动作统一为『喂』，所有素材入口最终汇到同一选择菜单，不增加额外学习成本」）。

拍平后的规则：

| 位置 | 内容 | 什么时候在 |
|---|---|---|
| 「喂」入口 | 输入框 + 目标下拉（index 0 = 灵感池（不挂靠），i+1 = 第 i 段）+ 「喂进去」 | **永远在**，位置不变 |
| 主题头 | 期名 + 「切换」；无主题时整块换成「立项」（期名输入框 + 立项按钮，名字空着按钮禁用） | 永远在 |
| AI 看着说 | `next_step` 的 why + next | 有主题时在，**只是一行提示，不挡任何入口** |
| AI 提议 | 结构增/并/撤/收，由人裁决 | 有提议时在 |
| 叙事结构 | 节拍行（行内「够了，这段讲清了」）；线 `Strand` 锚在**节拍行 + payoff** 上 | 有主题时在 |
| 完成度 + 收口 | 估算条 + 「够了，收口」 | 有主题且 ≥1 段就能点，**不等任何步骤** |
| 封顶后 | 草稿 + 跳发布页 | 封顶后 |

⚠️ **删掉的东西**（别再装回来）：`STEPS` 常量、`step_index()` 闸门、顶部五节点阶梯、「现在这一步 · N/5」。它们把面板变成了向导，而不是工具。

### 2.11 ★ 零前置数据（v0.7.1）

面板与配置里**不许出现任何"别人已经写好的内容"**：没有排期表、没有示例期名（E004/E005/E006 这类）、没有预填素材、数据库也不 seed。

- `config.SEED_TOPICS` 已删除。曾经它让面板一打开就列出「E005 · MCP 到底创新在哪 / 你收的几条都是 MCP 相关」——人还没记任何东西，界面已经在替他决定要做什么。
- 立项只有一条路径：**自己给这一期起个名** → 立项（有灵感池素材就一并带进来）。名字空着时按钮是禁用态，**不编默认名**。
- **空白就是空白**：空态的球是虚线圆 + "+"，空态的灵感池写「还是空的」，立项那格是空输入框 + 灰掉的按钮。

**测试同步**：`uitest.py` 断言"面板里搜不到任何 `E00` 字样的按钮"、"名字空着时立项按钮禁用、打了名字才可用"、"期名就是人打的那个"。

### 2.12 ★ 结构由人直接编排（v0.7.2）

v0.7.1 之前，改结构只有一条路：**AI 提议 → 人点采纳**。这不对——AI 没提议的时候（或它提议的方向不合意时），人就只能干看着。既然叙事结构是人手里那绞线，它必须能**手动增删改排**。

每个节拍行右侧常驻一排小按钮（哑色，不抢注意力）：

| 按钮 | 做什么 | 语义边界 |
|---|---|---|
| **＋** | 在这一段**后面**插一段，并**立刻进入改措辞态**（加完就说，不多一步） | 新段 `origin='human'`；没写内容就当没加过（回车留空＝撤回） |
| **↑ / ↓** | 往上/往下挪一格（第一段的 ↑、最后一段的 ↓ 停用） | 顺序影响"下一步"先推哪段 |
| **改** | 就地改这一段的措辞（Enter 提交，Esc 退出） | 清空后回车＝放弃，**不动原值** |
| **×** | 撤下这一段 | 段里的素材退回「未指派」，**一条不丢**；只剩一段时停用 |

**硬约束**：`origin` 字段区分"谁放的"（ai / human）——事后再看还认得出这个节点是谁加进来的。
**封顶之后**：只留「改」（改错字不该被锁死），＋/↑/↓/× 收起 —— 动了结构才是大事。

**为什么不做成"编辑模式开关"**：多一次点击才能改，等于又变回流程了（§2.10 的同一个理由）。

**两个实测踩到的 PyQt 坑（已写进 `panel.py` 文件头）**：

1. 槽的参数个数只能 ≤ 信号的参数个数。`returnPressed` 是 **0 参**信号，接了 `lambda _: ...` → 按键那一刻抛 TypeError → **PyQt 对槽里的未处理异常直接 qFatal，整个进程退出**（退出码 `0xC0000409`），traceback 还会随 stderr 缓冲一起丢掉，极难定位。定位靠"把提交切成几段打点 + 断开信号"才逼出来。
2. 刷新会重建整棵子树，而刷新常常就是从该子树里某控件的信号里发起的 → 旧内容必须 `takeWidget()` + `deleteLater()`，**不能**让它被 `setWidget` 同步删掉。

**测试同步**：`uitest.py` 新增"手动编排"整段——加一段（含 origin=human 与自动进编辑态）、改措辞（含"清空＝放弃"）、上移换位、边界禁用、撤下（含"素材退回未指派"计数）。按键走 `QTest.keyClick` 真按键，不走直接调槽。

### 2.13 ★ 手感：不闪、能拖（v0.8.0）

三个体验问题是同一批动作暴露出来的：**点一下就闪、只能拖标题栏、结构得靠按钮一格一格挪**。

| 症状 | 真因 | 改法 |
|---|---|---|
| **点一下就闪** | 每次动作都重建整棵子树，`QScrollArea.setWidget()` 会把滚动位置重置回顶部 —— 人看到的是内容"跳"了一下 | 重建前记住滚动位置、重建完还回去（**正在改措辞时除外**：那一行要滚进视野）；建的过程中先 `setUpdatesEnabled(False)`，边加控件边画也是闪的来源 |
| **拖不动** | 拖动只认标题栏那 48px（`e.position().y() <= TITLEBAR_H + 16`），面板主体全被滚动区吃掉 | 装一个**应用级事件过滤器**：按下落在"装饰面"（卡片 / 标签 / 空白）就拖动窗口；按钮 / 输入框 / 下拉 / 滚动条 / 节拍行一律跳过，不抢它们的手势。带 **6px 阈值**（和球同一套）：手抖几像素不算拖 |
| 结构只能一格一格挪 | 只有 ↑↓ | 节拍行**自己就是把手**（`BeatRow`）：按住行上下拖 = 换位；拖动中目标行描金边；松手落地 |

**踩到的两个坑**：

1. **别指望事件"自己透上去"**。`WA_TransparentForMouseEvents` 的语义是连**子控件**一起吃不到鼠标（Qt 文档原文 "and its children"），而 `QTest.mouseClick` 是直接投递给目标控件的、**绕过命中测试** —— 测试全绿也证明不了真机点得到。所以既不用它、也不赌冒泡，改用应用级过滤器（投递前就能看到）。
2. 被接受的按下会向上冒泡（Strand → viewport → `QScrollArea` → `Panel`），过滤器因此会被同一按多次叫到；**`Panel.mousePressEvent` 里绝对不能再动拖动状态**，否则它会把过滤器刚记下的那次拖动清掉（实测：点空白处拖不动就是这么来的）。

**测试同步**：`uitest.py` 新增"拖动"一段——行内拖动真的换了位、刷新后滚动位置还在原处、内容空白处按下进入拖动状态且面板真的跟着走。

### 2.14 ★ 对话：和 AI 聊思路，用对话改结构（v0.8.0）

前面的愿望一直缺一角：**只能"喂素材"，不能"聊思路"**。想改结构更别扭——要么等 AI 提议、要么自己一个个点。补上「聊」：

- 面板里一张常驻的**对话卡**（在主题头下面）：线程 + 独立输入 + 「说给它」。说人话就行（"我想从『成本』这个角度切"），不用管格式。
- **它的话：一条回复 + 可能要动的结构。** 动结构必须**先列出来**（"它会动这些：第 1 段改成…；在第 2 位插一段…"），人点**「照做」**才落地 —— 这是项目铁律（宣布完成的权力在人、结构动不动人裁决）在对话里的延续。
- 模型能下的动作（段号一律 **1 起**）：`add / rename / drop / move / payoff`。落地时**对照真实段数再校验一遍**，越界/对不上的直接丢掉（宁可不动，也不乱动）；只剩一段时不许 drop。
- **模型不通就如实说**：线程里插一条灰字"模型没接上（看标题栏那行状态），所以这句没人回"，绝不编一条假回复装作在工作。模型超时/返回非 JSON 同样照实说一句。
- 对话**只活在这一次运行里**（`App.chat`，按 topic id 分），不进库 —— 不给"随手记"这种轻动作添一套聊天记录要维护。
- `Ctrl+Enter` 看光标在哪：在对话输入里就是「说给它」，在「喂」那一格就是「喂进去」。

**两个实测出来的坑**：prompt 模板忘了套 `% (...)`（模型收到的是带 `%s` 的原文）；llmtest 的桩里，对话 prompt 也含"最想让人记住"这类词，**分支顺序不对就会命中旧分支**（桩的匹配要按"最独特的那句"排前面）。

**测试同步**：`llmtest.py` 用桩验完整对话链路——我一句 / 它一句、**没点照做前结构一个像素都不动**、照做后按第 2 位插段且第 1 段改名、越界那条被丢掉、模型抛异常时给诚实说明；`uitest.py`（模型关着）验"不假装能聊"。

### 2.15 ★ 成片稿：分镜表 + 逐段口播稿 + 素材落盘（v0.9.0）

§2.13/§2.14 解决的是"顺手"和"能聊"，但最要紧的那个缺口还在：**封顶之后交不出东西**。这一版补的就是它，外加素材从"文字"升级成"真文件"。

**① 素材落盘（`assets/`）**

- 拖文件到面板、或点「＋ 文件」选文件 → **复制**进 `%LOCALAPPDATA%\Skein\assets\topic-<id>\`，**原件不动**。复制而不是记路径：素材常在下载目录/桌面，被删被移就断了；复制一份这个期才真的自足。
- 落在哪个段由**同一个目标下拉**决定（0 = 灵感池）—— 文字和文件走同一套目标，不新增第二个菜单（§2.10 的硬约束）。
- 图片素材在面板上有**缩略图** + 「打开」；同名不覆盖，自动退到 `名字-1`。
- 类型按扩展名判（image / video / audio / text / file），判不出来就写 `file`，**不猜**。

**② 逐段口播稿 + 分镜表（封顶后的交付物）**

一张表，每段一行：**段号｜这一段要回答什么｜口播稿｜要什么画面｜手上素材数**。

- 口播稿是**口语、能直接念**的，不是要点；画面要具体到"观众看到什么"。
- **一条模型调用写全部段**（`llm_storyboard`），返回按段号 1 起的条目，越界/对不上的直接丢。
- 没模型或失败 → 降级到本地规则：口播稿 = 把这一段已有素材串起来（**不编素材里没有的事实**）；画面 = 有图/视频就说用它，没有就如实写"待定 + 需要什么样的画面"。
- 「复制分镜表」/「导出 Markdown…」/「打开素材文件夹」；还能「重写成片稿」按现在的素材再让模型写一版。
- **旧的那坨"封顶草稿"删掉了**：两个产出会互相打架，只留分镜表一个交付物。

**测试同步**：`llmtest.py` 验封顶后模型写稿（含越界丢弃、导出非空）；`uitest.py` 用真文件验"复制进 assets/、原件还在、同名退号、面板真画出缩略图"，并验分镜表 Markdown 的表头与行数。

### 2.16 ★ 主题可改 + 节点可展开深入（v0.9.1）

**① 主题可改 —— 「把主题写对」和「换一个主题」是两件事**

以前只有一个「切换」（挂起整期，回到无主题态再重新立项）—— 改个错字要重开一期。现在主题头上常驻**「改期名」**，payoff 卡上常驻**「改」**：都是就地变成输入框、回车提交、Esc 退出。**只动这两个字段**，结构和素材一个不碰。

**② 节点可展开 —— 点标题 = 展开 / 收起**

- 节拍行标题前面有 `▸ / ▾`，**点标题**即展开（沿用已有的 6px 阈值：拖动还是换位置，两者不抢同一个手势）。
- 只有**标题那一块**算"点节点"；点素材那几行不算（那里可能要选文字）。实现上 `BeatRow` 记住 `header` 子控件，release 时用 `header.geometry().contains(pos)` 判。
- 展开出来的深挖区分两件事，因为**要的结果不一样**：

| 按钮 | 它给什么 | 存到哪 |
|---|---|---|
| **详细论证这一点** | 一段能站得住的推理：主张 + 2~4 条支撑 + **还缺什么** | `beat.deep`（是这一期的内容，会进库） |
| **就这一点发散** | 2~4 个能长成新段的方向，每条带依据 | 只活这次运行；点**「升成一段」**才变成段 |

- 两条路都**只喂这一段的素材**，并要求模型"素材撑不住就直说缺"——宁可写出缺口，也不要一条看起来很有力的假论据。
- 没模型 / 失败 → 本地规则那版：论证 = 把手上素材排成"要立住的点 + 手上有的 + 还缺什么"；发散 = 从这一段素材的术语里提方向。**两种降级都会在界面上明说是本地规则**，不冒充模型。
- 「升成一段」复用 `insert_beat`：新段插在这一段**后面**，依据那半句（`｜…`）自动去掉。

**测试同步**：`uitest.py` 验改期名/payoff 后**段数不变**、真点标题能展开、展开后两个按钮都在、详细论证走本地规则且**明说降级**、发散→升成一段（段数 +1 且插在后面）、再点一次收起；`llmtest.py` 用桩验模型版论证落库、发散丢掉过短那条、升段时去掉依据。

### 2.17 ★ 灵感池是一口池子（v0.9.2）

名字叫池子，界面却是一行行列表 —— 列表能操作，但**读不出池子的任何东西**：多满、成分是什么、攒到哪了。这一版把它做成真的一口池子。

**形态（`pool.py`，694 行面板之外单独一个文件）**

- **液态玻璃**，和球同一套材质：半透明机身（桌面透出来）+ 折射壁 + 顶部环境光 + 缓慢扫过的扫光带 + 左右两条色散细边 + 菲涅尔边缘光。
- **液面以下有液体**：素材是**泡在液体里**的。少了这一层，池子只是一块圆角玻璃板（第一版就是这样，一眼就看出来了）。
- **水位线是金的** —— 全面板唯一用金的地方（§theme：一个强调色只用一次），表示"这一池攒到哪了"。
- **喂进去的瞬间，那一块从池口落下来**（≤340ms，`@media` 式地尊重系统"显示动画"开关；关掉就静止）。
- **点一下池子才摊开列表** —— 列表是操作入口，不能丢，但默认收着，先让人看见"池子"。

**三条自我约束（写在 `pool.py` 文件头）**

1. **颜色不区分类型**。类型靠**形状**读：文字=细横条、图片=方块、视频=宽条、音频=窄条、其他=小方块。四类上四种颜色就是 AI slop。
2. **不预设容量**。池子没有"满了"这一说，所以**不做百分比水位**（给刻度＝凭空规定容量，违反"素材数量不预设"）。数量一多，块自动**变小变密** —— 读的是密度。
3. **常驻动效只重绘这一块**。球是独立小窗口，25fps 无所谓；面板是 520×736 的大窗口，所以池子只 `update()` 自己（Qt 只重绘该控件矩形），并且 `hideEvent` 里停表。

**改了 theme.py 的一条规矩**：原来写的是「玻璃只属于球和那一滴」，现在是「**玻璃只属于球和灵感池**」—— 池子装着"还没归属的东西"，是球那一滴积起来的地方，材质呼应是有理由的；其余地方仍然一律哑光。

**测试同步**：`uitest.py` 加一段——面板里有且只有一口池子、空池无块、点池子摊开列表且池子不被列表换掉、喂一条池子里多一块且块的 `kind` 正确、5 条时成分按类型分。**落下动效单独验**（走查里池子是停住的，否则截图会拍到块正在下落的半路 —— 第一版截图就是这么拍歪的）：拿临时池子把动画打开，验"喂进来会记下一条落下动效、再喂一块就再落一块"。`pool.py` 也因此加了和 `panel.py` 一样的 `ANIMATE` 开关。

> 📌 v0.10.0 补注：这口**灵感池**只在**还没有主题**时出现（那时攒的是"还没决定给谁的东西"）。有主题时面板里那口池子是 §2.18 的**叙事结构池**，两者不会同时出现，别混。

### 2.18 ★ 池子＝叙事结构主视图（v0.10.0）

老板定稿（原话）："像游戏一样，放一个空旷的水池，然后每一个叙事或者说视频的段落都是一个漂浮的球，但是这个球是有编号的，这个编号也就意味着视频段落的先后顺序，然后有一些没有被标记的球就没有编号，然后用户可以去对池中的球增删改查"；并补一句"没编号的球也是在同一期视频里的，这说明视频的整体段落还没有编排好，然后球里面可以包含各种文字图片和视频，并且 ai 会对每一个球进行一个短评"；以及"用户不动球就不会动"。

名字叫池子、结构区却是一行行列表 —— 这版把**叙事结构区整个换成一口水池**（`basin.py`，独立文件）。

**形态**

- **水体**：波面由**三组不同波长的正弦叠加**（不是一条上下平移的直线）+ 水下**光斑**（caustics，几条缓慢横移的亮带）+ **深度层线** + **涟漪** + 一道缓慢扫过的环境光。水越深越蓝越暗。
- **段球**（大球）＝视频的一个段落：清透天蓝玻璃球（镜面高光 / 内折射亮斑 / 底内反射 / 投影四层叠出"玻璃"），**编号是金的**（全面板唯一用金处之一）。**球大小＝这一段手上素材多少**。
- **素材球**＝挂在段球周围一圈上的小球，**一颗素材一颗球**（超过 8 颗收成「+n」）；它们是"球里面包含的各种文字/图片/视频"在池子里的样子。
- **未编排球**＝**同一期里还没排进顺序的段落**：混在同一口池里，只是暗一档、下挂一颗「未编排」，不占编号。

**三条语义（改代码前必须守住）**

1. **位置不表达顺序，顺序只写在编号里**。拖球只挪位置（往下拖＝沉得更深＝更暗），怎么拖都不会把顺序拖乱；要改顺序＝改编号。
2. **球放定就不动，只有水在动**。自主漂移、浮力呼吸、随波起伏、素材球公转**全部删掉**（第一版做成了自由漂浮，老板否掉）。球的位置进库（`beat.px/py`，千分比），重开这一期还在原地。
3. **未编排球不进下游**。它算这一期的段落（能喂素材、能有短评），但不计入编号、不进 `brain` 的任何计算（storyboard / 完成度 / 提议 / 对话段号），否则 `seq+1` 那套段号会错位。

**数据层**（`store.py`，仍是原地迁移）

- `beat` 加四列：`placed INTEGER DEFAULT 1`（老库的段默认已编排）、`note TEXT DEFAULT ''`（AI 短评）、`px/py INTEGER DEFAULT -1`（千分比位置，-1＝还没放过，按自适应布局落座）。
- 新函数：`add_beat_unplaced`、`place_beat(bid, index)`、`unplace_beat`、`reorder`、`set_beat_note`、`set_beat_pos`、`list_placed`。
- `reorder(tid)`：把**已编排的排到 seq 0..n-1、未编排接在后面** —— 这样 `brain.py` 里 8 处 `b["seq"]+1` 一行都不用改。

**面板**（`panel.py`）

- `_beats` 换成「**池子 + 选中球的操作条**」：操作条 = 措辞 / 编号（留空＝变回未编排）/ 移出编排 / 撤下 / 素材逐条 / 详细论证这一点 / 就这一点发散；池子下方常驻「**投一颗新球（未编排）**」。
- **删掉** `BeatRow`、行内拖动换位（`_drag_row/_drop_row/_row_at`）与**纺线 `Strand`** —— 池子里没有东西可锚了；顺序改由编号承担。`GUTTER` 随之收窄（原来 34px 是给线留的）。
- 「喂」的目标下拉不再用索引算术，改成**按球 id 取值**（含未编排球，标「未编排：…」）。

**AI 短评**：每个球一句（存 `beat.note`）。**本版先用本地规则**（`brain.comment_local`：按状态+素材数+措辞给一句），**模型版下一版接**（一次调用给所有球各出一句，失败退回本地那句）—— 这样先把池子的手感和语义钉死，再上模型。

**测试同步**：`uitest.py` 重写关于结构区的断言（球数＝段数、编号连续、未编排球外观与「未编排」小字、改编号后编号收拢、双击空白投新球、素材球数＝该段素材数、选中球后操作条出现、球不动而水在动），并把 `basinmod.ANIMATE` 一起停住以保证截图确定；`pool.py` 那口灵感池的断言照旧（它只在无主题时出现）。`llmtest.py` 加短评桩。

### 2.19 ★ 桌面版：快捷方式直连源码（v0.11.0）

老板原话（2026-10-11）："帮我把 task-orb 做成桌面版自动随代码更新，类似于本地的这个 studentbuddy"。

**定位澄清**：**不是** studentbuddy 那种「内置运行时 + 打包安装」的冻结包。Skein 是 Python 源码程序，冻结包每次改动都要重新打包发版，**做不到"随代码更新"**。所以这里走 **快捷方式直连源码** —— 桌面图标每次双击都跑 `app\main.py` 的**当前源码**，改完代码下次启动自动生效，永不重打包。

- **启动器 `run-silent.vbs`**：无控制台唤 `pythonw`；依次在 PATH、`%LOCALAPPDATA%\Programs\Python\Python3*`、`py.exe` 同目录里找 `pythonw.exe`，找不到弹中文提示而非静默失败；工作目录钉在 `app\`。
- **图标 `app.ico`**：由 `tools\make_icon.py` 现生成六档（16/32/48/64/128/256）——**暖墨圆角砖 + 一枚开口金色环**，对应产品那颗常驻悬浮球与品牌金 `#FFD01F`。改品牌色后重跑脚本即可，不存手画位图。
- **桌面快捷方式 `Skein.lnk`**：目标 `wscript.exe "…\run-silent.vbs"`，起始位置 `task-orb\`，图标 `app.ico`。**不开机自启**（老板定：手动启动）。

**两条实测踩到的坑**：① VBScript 里 `Dim … sub` 撞保留字 `Sub` → 语法错误（`缺少标识符`），wscript 弹「Windows Script Host」错误框；② `.vbs` 含中文**必须**存成 UTF-16LE + BOM，否则 wscript 按 ANSI 读、中文全部乱码。

**三条边界**：① 桌面版**不是**第二套代码，就是源码本身（改代码＝改桌面版）；② 依赖本机 Python 3.11+ ＋ PyQt6 ＋ pywin32；③ 不安装、不写注册表、不占 `Programs\` 目录。

**验证**：双击 `Skein.lnk` → 进程 `pythonw … task-orb\app\main.py` 拉起（实测 PID 已确认）。

### 2.20 ★ 触发式排版：常驻的只有「聊」（v0.12.0）

老板原话见 P-015。问题：有主题时**每张卡都顶着一个小标题 + 一大段 `dim` 说明**（喂 / 聊 / 池子 / 深挖 / 完成度…），收口还独占一张五层卡（标题 + 16px 数字 + 进度条 + 说明 + 大按钮），看着像网页表单而不是一个常驻的球。

**新规则 —— 常驻只有「聊」，其余都收在触发条后面**：

| 位置 | 内容 | 默认 |
|---|---|---|
| 主题头 | 期名（悬停出「形态 · 目标张数」）+「改期名」+「切换」 | 常驻 |
| PAYOFF | 一行 `PAYOFF 那句话 [改]`（不再独占卡片） | 常驻 |
| AI 提示 | 一行 `→ 下一步`，**why 收进「?」**（不再是一张卡） | 常驻 |
| **触发条** | `[＋ 喂] [池子 · N] [提议 · n]` … `≈62% [✓]` —— 一枚枚小芯片 | 常驻（极窄） |
| **聊** | 对话线程 + 输入 +「说给它」 | **常驻主体** |
| 喂 / 池子 / 提议 | 点触发条上对应芯片才**就地展开**，再点收起 | **收起** |
| 未指派 / 成片稿 / 编排包 | 只在有内容 / 封顶后出现 | 按需 |

- **收口**：整张卡删掉，换成触发条右端一个**小勾按钮**（悬停「够了，收口 —— 上限由你定」），旁边跟 `≈62%`（悬停说明「上限钉在 92%」）；封顶后同一位置换成一行绿色 `✓ 已确认足够`。进度条 `Bar` 随之删除。
- **引导触发式**：说明句默认**一律不占版面** —— 一句话的挂 `setToolTip`；多句的（聊的格式约定、池子拖球语义、点球说明、成片稿 / 编排包是什么）收进标题旁一个小「?」，点一下才就地展开一行。
- **铁律没变**（§2.10）：触发条只是"按需展开"，**不是阶段闸门**；任何入口点一下就在眼前，不按机器顺序走。

**踩到的坑**：`_balls`（球列表）原先由 `_feedbar` 顺手赋值 —— 抽屉一收就没人赋值了，「未指派素材」的「指派到…」会拿到空列表。改成在 `refresh` 里**无条件**从 state 取一次，喂 / 池子只是"渲染时不渲染"。

**测试同步**（`uitest.py`）：折叠后"直接拿 input / combo / 池子"的断言必然失效，走查改为**先点触发芯片再断言**，并补两条"默认收着"的反向断言；收口按钮改按 `objectName="cap"` 定位（文案已从小字变成一个勾）。**按钮文案与 objectName 全部保留**。

### 2.21 ★ 确认要能取消：四处撤销（v0.13.0）

老板原话见 P-016「确认是要可以取消的」。判据只有一条：**人按下的确认，人要能收回**。

| 确认 | 怎么撤 | 实现 |
|---|---|---|
| **封顶（收口）** | 触发条右端那枚 `✓ 已确认足够` **可点** —— 点一下 `uncap` | `store.set_capped(tid, 0)` |
| **逐段「够了」** | 选中有编号的球 → 操作条上多一枚 **「撤销确认」** | `store.set_beat_lock(bid, 0)` |
| **对话「照做」** | 触发条上 **「↩ 撤回」**（照做之后才出现） | 整期快照还原 |
| **提议「采纳」** | 同上（同一枚「↩ 撤回」） | 整期快照还原 |

**为什么「照做 / 采纳」用整期快照而不是逐条算逆操作**：这两处会牵动段增删、重排、素材改派、payoff、capped —— 最容易漏的正是「撤下一段时素材退回未指派」这类**跨表副作用**。`store.snapshot_topic(tid)` 把 topic / beat / 这一期的 material 整块照下来，`restore_topic` 再整块换回去（**行 id 原样保留**，素材一条不丢）。只碰这一期自己的行，灵感池（`topic_id IS NULL`）不受影响。

**边界**：撤销栈只认**当前这一期**（换期即清空，最多留 20 步）；「↩ 撤回」只在有得撤时才出现在触发条上（空的就不占版面）；撤回后 `dismissed` 与 `_llm_props` 一并清掉，结构回到动它之前。

**测试同步**：封顶后断言换成 `objectName="capdone"`（可点的那枚），并新增「取消封顶 → 小勾回来 → 再封顶」；新增「已确认的球上有『撤销确认』→ 改回待确认 → 再确认」；3b 采纳后新增「出现『可撤回』→ 撤回 → 段数/锁定回到动它之前 → 栈清空」。

### 2.22 ★ 搜素材 + 直通来源（v0.13.0）

老板原话见 P-016「配上搜索功能，方便搜集素材」「提供跳转链接……直通相关素材源」。

- **免 key 免费通道**（`websearch.py`，**只用标准库**）：先取 Bing 的 **RSS**（结构化、好解析），拿不到再退**网页 HTML 解析**（`parse_rss` / `parse_html` 都是纯函数，可离线单测）。**只连固定主机**（`www.bing.com`），不接受外部传入 URL —— 没有 SSRF 面；失败把原因（`type(e).__name__` / "没搜到"）**如实**带回界面，不假装搜到了。

### 2.26 ★ AI 原生工具调用：改池子里的任意一颗球（v0.16.0）

老板原话见 P-019。核心：**让对话 AI 有"改软件内特定数据"的能力** —— 池子里的**每一颗球**（已编排 + 未编排）都能改。以前对话只能用 `at:段号` 改「已编排段」，改不到未编排的球，段号还会在增删重排后漂移。

**协议 = 混合**（`brain.llm_chat`）：

1. **优先原生工具调用**：`llm.chat_message(messages, tools=TOOLS, tool_choice="auto")` 返回带 `tool_calls` 的 message，`_actions_from_calls` 解析（`arguments` 可为 JSON 字符串）。
2. **降级结构化 JSON**：网关不支持 `tools`（报错/忽略）时，正文里带 `{"reply":…,"actions":[{"tool":…,…}]}` 也认；两条来源统一归一成 `[{"tool":名,"args":{…},"text":人话}]`。

**上下文**（`_pool_ctx`）：列出**整口池子** —— 已编排报 `#id [第 N 段 · 状态]`、未编排报 `#id [未编排 · 状态]`，每颗附最多 2 条素材原文；末尾列未指派素材 `- #mid body`。**只给统计不给原文模型会编素材**（沿用 §2.9 教训）。

**落地闸门**（`main._apply_one`）：仍是**提议 → 人点「照做」才动**（守 P-010/P-013）。逐条按 `tool` 分派，球先用 `store.get_beat(id)` 复核**存在 + 属于本期**，不存在/越界一律不动；`drop_ball`/`unplace_ball`/`merge_balls` 有"至少留一段在编排里"的守卫；`assign_material` 校验素材确实未指派且属本期。`_norm_tool` 在解析层就做了边界校验（question 2~80、note/deep 2~500、script 6~400、shot 4~200、payoff 6~60、position 1~999、merge 两端不同）。`_act_text` 把每条工具说成人话，给「它会动这些」和事后小结用。

### 2.28 ★ 一期记忆：一期一份、严格隔离（v0.17.0）

老板原话见 P-020（"我的大概的想法是一期视频一个记忆"）。核心：**一期节目有一份自己的内容记忆，期与期绝不串味**。以前对话只在**这一次运行**里活在内存（`self.chat`），重启即丢、也没沉淀 —— AI 每次接话都从零开始。

**落盘（`store.py`）**：新表

```sql
CREATE TABLE IF NOT EXISTS chat(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  topic_id INTEGER NOT NULL, seq INTEGER NOT NULL,
  role TEXT NOT NULL, text TEXT DEFAULT '',
  actions_json TEXT DEFAULT '', ts TEXT);
```

`actions_json` 装 `{"actions":[…],"done":bool,"summary":str}`（一条 AI 回复的结构改动 + 是否已照做 + 小结），这样**重启后「已照做」态不丢**。「记忆」本身不进新表，而是给 `topic` 加一列 `memory TEXT DEFAULT ''`，存 **3~6 条「这一期已定的口径」bullet（是结论，不是聊天原文）**。老库靠 `store.MIGRATIONS` 原地升列（`PRAGMA` 判列后 `ALTER`，幂等）。

**取数一律按 `topic_id`**（`store.list_chat(tid)` / `get_topic_memory(tid)`）—— **绝不跨期**，这是"一期一个记忆"的硬约束。

**蒸馏（`brain.llm_distill`）**：把**这一期的对话 + 结构**交给模型，蒸馏成 3~6 条口径（各 ≤40 字，只留已确定的结论/取舍）。触发点两个（`main._kick_distill`）：**你点「照做」后刷新一次** + **对话满 6 条兜底**。跑在**后台线程**，结果回主线程落库（`_distill_land`）；**失败/没模型就保留旧记忆，绝不阻断主流程**（同 §2.9 铁律）。

**注入（`brain.llm_chat`）**：拼 user 串 = `期名 / payoff` + 现有 `_pool_ctx`（整口池子）+ **`【这一期已定的口径·记忆】`** + **`【最近聊过】（最近 8 条）`** + `他刚说：…`。记忆让 AI"记得这一期已经定过什么"，最近 8 条让它接得上话头 —— 两者分工（借鉴 ChatGPT/Claude 的 saved memories vs reference history 分离）。

**参考的开源/产品做法**（P-020 要求说明）：LangGraph（`thread_id` 隔离 + summarization 滚动摘要 + 保留最近 N 条）→ 一期记忆主结构；Letta/MemGPT（human 记忆块＝用户画像、常驻、限长）→ user.md 形态（§2.29）；mem0（ADD/UPDATE/NOOP 去重）→ 摘要刷新防重复；Zep（`invalid_at` 失效不删）→ 被推翻的口径**标作废不物理删**（本版先留旧行、由下次蒸馏覆盖）；Cline Memory Bank（分层 md）、Cursor/AGENTS.md/CLAUDE.md（分层加载、<200 行）→ user.md 是"user 层" + 限长；Generative Agents（reflection）→ "照做后刷新"。**故意不做**：向量检索/RAG、跨期内容引用。

### 2.29 ★ user.md：跨期用户记忆（只读，人自己写，v0.17.0）

老板原话见 P-020（"可以记录用户的一些习惯然后给一个user.md"）。**内容记忆按"期"隔离，用户画像按"人"累积** —— 分两层（借鉴 Cline Memory Bank / AGENTS.md 的分层加载）。

**文件**：`%LOCALAPPDATA%\Skein\user.md`（与 `llm.json` 同目录，`config.USER_PATH`）。纯 Markdown，**限长**（`brain` 读时最多 200 行 / 8KB，防有人贴一整本书把上下文撑爆）。

**只读**（P1 甲）：**应用第一版不自动写它**，内容由用户自己编辑；预留 `by: auto|user` 来源标记（`config.ensure_user_md` 建模板时打 `<!-- by: user -->`，将来若要自动写再区分来源）。**不自动写**的理由：画像写错比不写更糟，且这是"跨期"的信息，误改会污染每一期。

**注入**（`brain.sys_base()`）：设置里填了系统提示词就用人的、否则用通用兜底，末尾**只在该文件存在且非空时**追加一段 `【关于这位用户的习惯（他自己记的，只作参考）】` + 正文。文件不存在＝**行为与之前完全一致**（`sys_base()` 返回原值）。

**入口**（`panel.py` 设置抽屉）：齿轮抽屉第四组「跨期记忆 · user.md」→ 一枚「打开 user.md」按钮 —— 文件不存在就先落一份带 `by: user` 的空模板（**只在人点它时才建**），再用默认编辑器打开。

### 2.30 ★ AI 按期推荐搜法：可点芯片（v0.18.0）

老板原话见 P-021（"我们的搜索肯定是没有其他的软件做的好的，所以我们的ai要根据目前这一期视频的情况去推荐对应的搜索提示词"）。定位：**搜索质量不是 Skein 的强项，AI 的强项是"懂这一期在讲什么"** —— 所以不跟搜索引擎比排序，而是让 AI 把"这一期该去搜什么"变成几条**可直接点的搜索词**。**最基本的搜索能力照旧保留**（§2.22 的 Bing 免 key 通道，推荐词点下去就走它）。

**生成（`brain.llm_search_queries(topic, beats, mbb, focus=None)`）**：把**当前这一期**的上下文交给模型 —— 期名 / payoff / `_ctx` 结构快照（每段问题 + 前 2 条素材原文）/ 可选的 `focus`（**选中的那一颗球**：只就这一段推荐）。要求给 **2~4 条**能直接拿去搜的**具体查询词**（不是话题名、不是问句堆砌、要能落成关键词，尽量带这一期的术语/专有名词），每条 ≤ 30 字。返回 `list[str]` 或 `None`（没模型 / 失败 / 不够 2 条 → `None`，调用方静默降级）。

**落地（`main.py`）**：`suggest_queries(focus=None)` 后台线程跑，**代际计数器 `_sq_gen`** 丢弃过期结果（与 §2.9 同款）；结果落 `_sq`（list）/ `_sq_busy`；`_ui_extra()` 出给面板。**没模型就什么都不显示**（不编假推荐），**不阻断**任何主流程。

**界面（`panel.py` 搜素材抽屉，守 A·纪律）**：搜索框下面一行小按钮「**AI 帮我想几个搜法**」；点它 → 显示"正在想搜法…" → 拿到后列成**可点芯片** `_chip`，点一下 = 把芯片文字填进搜索框并走 `search_web`（**直接复用现有搜索链路，不新增搜索实现**）。选中某颗球时按钮带 `focus`，只推这一段的搜法。芯片纯文字、不加字形；金色仅用于"当前正在搜的那一条"。

**与 §2.22 的分工**：§2.22 是"**给你一个框、你自己想词**"；§2.30 是"**AI 替你想词、你只管点**" —— 两条并存，框还在。

### 2.31 ★ 原生 AI 接 tinyfish MCP：联网搜索（只读，默认开，v0.19.2）

老板原话见 P-021（"最基本的搜索能力还是需要的，所以你可以去让原生ai使用tinyfish的mcp服务"）。定位＝给**原生 AI**（`brain.llm_chat`）补一条**联网搜索**的腿；搜索质量照旧不跟搜索引擎比（§2.30 由 AI 替人想词），这里只要"**能搜、能读**"。

**为什么不用老板给的 `npx -y mcp-remote …`**：本机 `npx` 是坏的（解析到野文件、报 `Cannot find module`）。故 `mcp.py` **直调全局安装的 `mcp-remote` 的 `dist/proxy.js`**，与它讲 **stdio JSON-RPC**（`initialize` → `notifications/initialized` → `tools/list` → `tools/call`）。OAuth 由 mcp-remote 自己管，token 缓存在 `~/.mcp-auth`，**本模块不碰凭据**（已完成一次 OAuth 登录）。

**只读白名单（`ALLOWED = ("search", "fetch_content")`）**：tinyfish 实测暴露 **31 个工具**，绝大多数是浏览器自动化 / 监控 / 钱包等**有副作用**的。只放行「搜 + 读」两种，其余**一律不暴露给模型** —— 既避免误触副作用，也让模型的工具清单短到能选对（§0.7 简洁优先）。工具名统一挂 `tf_` 前缀（`tf_search` / `tf_fetch_content`），避免和池子那 14 个球工具撞名。

**`app/mcp.py`**：`find_node()` / `find_proxy()`（设置里填的 > 常见安装位）、`enabled()`（设置 `mcp_enabled`，**默认开**：没写过就算开，显式 false 才关；开而 node/mcp-remote 找不到 → 握手失败、工具清单为空，行为等同没开）、`Client`（常驻子进程 + 线程锁串行化请求 + 后台读线程按 id 匹配回包、带超时）、`tool_schemas()`（转 OpenAI function schema）、`call()`（执行 `tools/call`，失败返回一句说明**不抛**）、`get_client()`/`reset()`（全局单例；设置改了即重连）。单次结果截 `RESULT_CHARS=1500` 防塞爆上下文 / 拖慢收口。**`get_client()` 连不上不缓存坏实例** —— 早先一次失败会缓存空壳、永久没搜索（v0.19.2 修）。

**搜索回环（`brain.llm_chat(..., mcp=None)`）**：`mcp` 非空时把 MCP 工具拼进 `tools`；模型若调 **MCP 搜索工具 → 当场执行**（只读）→ 拿搜到的内容**单独发一次"收口"请求**（**只带搜索结果、不带池子/历史/工具**，又快又不易超时）压成两三句；并把"你能联网"**明写进系统提示词** —— 只把工具塞进 `tools` **不够**：提示词不提搜索，模型会如实回"我这没接搜索工具"（v0.19.1 实测踩到的坑）。**收口失败也不空手**：直接用搜到的原文摘一段回复。**池子改球工具照旧只当提议**（攒进 `actions`，等人点「照做」才落地，P-010/P-013）。`mcp=None` 时行为与从前**完全一致**。**回复限长**：单条回复超 400 字截断（对话越聊越长，v0.19.2）；喂回模型的"最近聊过"从 8 条缩到 6 条、每条截 240 字（§2.28 记忆之外再加一道封顶）。

**接线与设置**：`main.say` 的 work() 里 `mcp.get_client()` 传进 `llm_chat`；开机 `_kick_mcp_warm()` 后台先把连接热起来（冷启动 ~5s，第一次对话不用白等）；设置抽屉新增**组 5「搜索 MCP · tinyfish（默认开，可关）」**（开关 + `node` 路径 + `proxy` 路径 + 服务地址，落 `settings.json`）。**为什么默认开**：P-021 原话"最基本的搜索能力还是需要的"——默认关会导致 AI 拿不到搜索工具、如实回"无法联网"（v0.19.0 上线当晚实测）；而 node/mcp-remote 缺失时本就是静默降级，默认开不会带来副作用。**铁律（守 §2.9 静默降级）**：连接/握手/调用**任何一步失败都返回空**，调用方**静默降级回 §2.22 的 Bing 通道**，**绝不卡主流程**。

**测试**：`llmtest` 加桩 MCP（`_StubMcp`）—— 验"搜索工具当场执行、参数原样传下去；同轮改球只当提议；系统提示词明说能联网；**收口轮超时也不丢整条**；`mcp=None` 走老路"；`uitest` 加组 5 断言（开关默认开、三个字段存在且能落盘）。两套走查都**桩掉 `mcp.get_client`**（默认开后否则每次 say 都会拉 node、打真网络）。compileall + uitest + llmtest 全绿。

### 2.33 ★ 对话体验：流式 · Markdown · 历史折叠 · 动效（v0.21.0）

老板原话见 P-023。对话是这一期的"主界面"，手感要跟上通用聊天工具。

**① 流式（`llm.chat_stream` → `brain.llm_chat(on_delta)` → `main` → `panel`）**
- `llm.chat_stream(messages, on_delta, ...)`：标准库 urllib 逐行读 **SSE**（`data:` 行），每段增量回调；**同构返回**聚合后的 message（content 全文 + 流式拼起来的 `tool_calls`）—— 上层照旧当非流式结果处理。实测网关支持（`text/event-stream`，首片 ~7s、之后 ~1s 吐完 141 片）。
- `brain.llm_chat(..., on_delta, should_stop)`：给了 `on_delta` 就走流式，否则走原来的一次性；**MCP 收口那轮也流式**，并先发 `on_delta(None)` **清空重来**（避免上一轮临时内容残留）。
- `main`：`_mk_delta` 把后台线程的增量**按 50ms 节流**成"当前全文"投进 `_cq`（每次 delta 都塞队列会淹掉 Qt 事件循环），`_stream_land` 带代际守卫防串台。
- `panel.push_live`：**只更新那一句"活体"**（`RichText.set_html`），**不整面板重建** —— 面板是"每次刷新重建整棵子树"，流式绝不能走 refresh。

**② Markdown 渲染**
- 用 **`markdown` 库**转 HTML（`fenced_code` / `tables` / `sane_lists` / `nl2br`），样式经 `QTextDocument.setDefaultStyleSheet` 注入，贴 A·纪律（字号 12/13/15）。
- **不装 QtWebEngine**（太重、与 QPainter 自绘美学不搭）：自定义 `RichText(QTextBrowser)` —— 关掉自身滚动条、按内容自适应高度，链接走 `anchorClicked → app.open_url`。
- `markdown` 加入 `app/requirements.txt` 与 CI 依赖；**失败退化为转义纯文本**（绝不抛）。

**③ 历史折叠**
- 默认**只渲染最近一轮**（`log[-2:]`，1 问 1 答），上面一条「展开历史（N 条）」细条；点开渲染 `log[-40:]` 并变成「收起历史」。展开态只活在内存（不跨期、不落库）。

**④ 通用对话效果 + 炫技动效**
- 等待态：还没收到首片时显示 `ThinkingDots`（三点呼吸，QPainter 自绘，不用字形）。
- 流式光标：`▍` 挂在句尾、520ms 闪烁；流式结束后由落库那条接替。
- 入场：最新那条消息 `QGraphicsOpacityEffect + QPropertyAnimation` **淡入**（只给"新来的"那块，不每条重播；`ANIMATE=False` 时全关，走查保持确定性）。
- 可中断：发送后输入框禁用、出现「停」（`should_stop` 让流式提前收口，**已吐出的部分照常落库**）。

**测试**：`uitest` 加 Markdown 渲染 + 历史折叠（默认 2 条 → 展开 6 条）断言；`llmtest` 加 `fake_stream` 桩（**复用 `chat_message` 的桩**，所有 monkeypatch 自动对"流式那条路"生效）+ 「增量拼起来 == 最终回复」「流式下工具调用照样带回来」断言。compileall + uitest + llmtest 全绿；真机流式实测通过。

### 2.34 ★ 回复质量 · 断信息 · 字号（v0.22.0）

老板原话见 P-024（"回复质量太低、总是断信息、字体特别小要放大一倍"）。

**根因（实测坐实，不是猜）**
- 网关**不截断**：绕过应用直接问"写 600 字"，回 1315 字、`finish_reason=stop`。所以"断"不是网关的锅。
- 是**自己上轮的"瘦身"矫枉过正**：① v0.19.2 为治"对话变长"加的 `len(reply) > 400 → reply[:400] + "…"`，**从句中硬切**；实测一条 414 字、完整收尾的好回复，**恰好会被它切掉**。② `_CHAT_TAIL` 写着"两三句就够、别复述、别分点"，把模型勒死。③ MCP **收口轮只把搜索结果丢回去**（"只挑一点、两三句话"），**没带用户问了什么** —— 模型不知道上下文，才会回出"这条帖子撞上了…"这种**接不上半句**（库里 id=10 就是它，85 字）。

**修法**
- **回复不再硬截断**：上限放到 4000（几乎够不着），正常一轮远不到。
- **提示词改成"把话说完"**：`_CHAT_TAIL` → "说人话、该展开就展开（一般三五句）、**别只写半截**、别照抄资料"；`user` 尾句 → "把话说完整"。
- **收口轮带回上下文**：给它「期名 + 他刚说 + 搜索摘要」，要求"用**完整**的几句话回他、别只写半截"。
- **上下文回补**：最近聊过 6 条×240 字 → **8 条×320 字**（历史折叠已在，不怕长）。
- **字号整体上移**（§A·纪律：仍是 4 档，只是每档上移）：`theme.FS_*` = **26 / 22 / 20 / 18**（原 15/13/12/11）；`panel._MD_CSS` 同步；按钮/输入内边距、圆角、滚动条宽度同步放大。面板 `520×736 → 640×820`，`PAD 16→20`、`GUTTER 16→22`、`TITLEBAR_H 48→64`，各处固定控件宽度（设置标签列 58→84、按钮 52/58/60→72/84/84 等）同步放宽。

**验证**：真机问"这期该从哪个角度切入" → 回 **414 字、三段、完整收尾**（旧代码会切在半句）；uitest 走查截图肉眼核对**无裁字/无重叠**；`uitest` 的"拖动面板"一条改为"小屏纵向可移 <60px 时如实跳过"（面板变高后 `_clamp` 会夹住，属环境限制不是回归）。compileall + uitest + llmtest 全绿。

## §5 已调研／已确认事实

**命名（P-011 的调研结论）**
- 直觉候选 **Tessera / Trellis / Forage 均已被占**（个人 AI 助手、YC 短租 AI、法律 AI、支付平台等），AI 赛道极度拥挤。
- 定名 **Skein**（/skeɪn/）：一绞线、线团；英语里亦指"一群飞鸟"——兼有"聚集"与"成形"两义，冷门、独占性强。
- 正式启用前仍需过一遍商标与域名。

**赛道与背景**
- 蚁小二/易媒/新榜矩阵通做分发，不管素材收集；Milanote/Notion 做整理，要主动打开；都不对 P-007 的"轻"。
- 老板在运营抖音图文号"奶蛙讲堂"（3D 黄胖蛙讲程序员）。机器：Windows，Intel Core Ultra 9 285H。

**可直接复用的本机资产**
- 跳转发布页：`native_tools.py:19-20` 已有 `computer.open_url` / `computer.open_app` / `shortcut.run`。
- 内容侧：奶蛙 E001~E024 排期 + 单篇 8 步 SOP 可反向生成骨架模板。
- 人设：角色资产卡 v1.1（#FFD01F / #FFF6E0 / #6FBF2A / #6B5D4F，固定口癖）。
- 采集能力：词镜已交付（网页正文/选区读取、划选浮层、OCR 兜底）——参照原则，不抄形态。
- 常驻置顶球：**零现成代码**（grep 无 topmost/overrideredirect/wm_attributes）。

**既有实机结论**
- UIA TextPattern 取文本**不依赖焦点** → 可"不打断阅读"地拿到选区；路线＝UIA 主 + 区域 OCR 兜底。
- Chromium 页面默认启动 ≤1s 即可直读。
- ⚠️ Windows 上"显示即抢焦点"**根本测不出来**，真正分歧点在**鼠标点击** → 探针必须测点击。

**方法论依据**
- 质性研究"饱和"：数据饱和（无新信息）/ 理论饱和（解释力充分）；质量而非数量是关键。
- 短视频叙事骨架：Hook→Problem→Solution→Proof→CTA；S.T.A.R.T.；Story Spine；**先写 payoff 再写 setup**。
- 人机分工 HITL：AI 提议，人决策；事实核查必须人做。
