02一条真实的流水线，和 Skein 现在的覆盖

绿 = 现在已经做到；黄 = 做到一半；红 = 完全没做。

已覆盖（Skein 现有） 半覆盖 缺口
① 选题 / 立意TOPIC
这一期讲什么、最想让人记住哪一下。
Skein：立项 + payoff人自己起名
② 结构 / 分镜骨架OUTLINE
每段要回答什么问题、顺序怎么排、哪段够了。
Skein：叙事结构 + 手动编排 + 对话改结构 AI 提议 → 人裁决
③ 素材收集ASSETS
截图、录屏、整段原文、B-roll——真文件要能进得来、找得到、能拖进剪辑软件。
Skein：现在只有文字（body 字符串，没有一次落盘） 缺：上传 / 拖入文件、缩略图、打开文件夹
④ 逐段讲法SCRIPT
这一段具体怎么说——口语稿，不是要点。
Skein：现在的"草稿"是一坨文字 要改成：逐段口播稿
⑤ 成片稿：分镜表STORYBOARD
一张表：第几段｜口播稿｜要什么画面｜手上有没有。这是"想清楚"交付给"动手剪"的那个物件。
Skein：完全没有 可导出 Markdown / 一键复制
⑥ 配音 / 字幕 / 粗剪ASSEMBLE
口播稿 → TTS 或真人录音 → 转写对轴 → 去废话 → 加 B-roll。
FunClip / auto-editor / Remotion Skein 不必自己做，但要能"交出去"
⑦ 出片 / 发布PUBLISH
导出可编辑工程（剪映草稿 / FCPXML），或直接落到平台。
pyJianYingDraft / capcut-cli / autoEdit_2 Skein 现在只有：三个发布页链接

一句话诊断

Skein 把 ①②④ 做得不错，③ 素材只到文字、⑤⑥⑦ 整段是空的。 也就是说：它帮你把"怎么讲"想清楚之后，没有一个能交到剪辑软件手里的物件。 这就是你说的「真正的成片 / 完整的成片素材」缺的那一段。

03Skein 该接在哪：三条路线

按你选的「分镜表 + 逐段口播稿」和「上传 + 粘贴文字」来评估。把握度是我的判断，依据写在后一列。

路线做什么工作量大头把握度 / 依据
A · 分镜表 + 逐段口播稿
推荐		 封顶后不再吐一坨草稿，而是逐段成表：口播稿 / 要什么画面 / 手上有没有；可导出 Markdown、可一键复制。素材支持上传文件与粘贴长文。 模型按段写稿 + 本地拼表；文件上传进 assets\ 并做缩略图 高。全在本机链路内：写稿是已有 LLM 通道，表格是纯拼装，文件是本地拷贝。不新增外部依赖，不引入"生成质量不可控"的环节。
B · A + 导出剪映草稿
第二步		 在 A 之后，把分镜表编译成剪映工程：每段一块字幕卡 + 占位素材，直接在你惯用的剪映里改。 对齐 draft_content.json 结构（可抄 pyJianYingDraft 的格式） 中。剪映草稿是无公开文档的私有格式，版本一变就可能失效；pyJianYingDraft(4.5k★) 与 capcut-cli(853★) 都活着，说明可行但需要持续跟版。建议做成"导出"而非"内置"。
C · 直接出片
不建议		 脚本 → TTS → 自动配画面 → 合成 mp4。 等于自建一个 MoneyPrinterTurbo 低。129k★ 的开源项目已经把这条路卷到极致；而且它替人做完了判断，与 Skein「判断权在人、AI 只提示」的立身之本冲突。

建议的落点

  • 做 A。它是"想清楚"和"动手剪"之间那张缺失的纸 —— 也是你能立刻拿去拍、拿去剪的东西。
  • 把素材从"文字"升级成"文件"。拖入 / 选择文件 → 复制进 %LOCALAPPDATA%\Skein\assets\ → 素材里显示缩略图 + 一个「打开文件夹」。这样剪映里能直接拖。
  • B 留作下一步的"导出"。不在第一版做，但格式上照着 pyJianYingDraft 留好接口（分镜表已经是天然的数据源）。
  • 对话已经能改结构了，顺手让它也能改口播稿 —— 说"第 2 段太学术了"就直接改那段稿子。

3.1对标对象：钉住"抄谁的什么"

按你项目里的规矩：功能必须有参照软件，钉死抄什么。

要抄的抄谁具体抄什么
分镜表的字段构成ArcReel 5.4k★段落 / 口播 / 画面描述 / 资产是否齐 —— 但把它从"生成流程"里剥出来，只做成一张可交付的表
意图驱动 + 人始终在环FireRed-OpenStoryline 3.5k★自然语言指挥 → LLM 规划 → 明确列出要动什么 → 人确认（Skein 的「照做」已经是这个形状）
口播稿"去废话"auto-editor 5.5k★只参考它"用静音/停顿自动修剪"的思路，Skein 侧表现为给稿子标出可删句
剪映草稿格式pyJianYingDraft 4.5k★直接对齐 draft_content.json 的字段（B 阶段才用）
字幕/对轴FunClip 6.4k★中文优先用 FunASR 而非 Whisper（只在真要做字幕时才接）

4.2这份调研不能说明什么

三条边界，先说清楚

  • 我只查了元数据，没有读它们的源码。星数和描述说明"外面看起来是什么"，不等于"质量真的好用"。要判断某个项目能不能直接抄，得挑一个把 README 和关键实现读一遍。
  • 星数会被时间放大。93k★ 的 OpenCut 和 129k★ 的 MoneyPrinterTurbo 都是"大众爆款"，不代表工程最扎实；反而 4.5k★ 的 pyJianYingDraft 这种"窄而深"的项目更可能真能用。
  • 活跃度我只看最后提交时间，没看 issue/PR 积压。标"停滞"的（如 autoEdit_2 两年未动）意思是"别指望它跟得上剪映版本"。

4.3下一步可以马上做的验证

  • 挑 pyJianYingDraft 读一遍草稿格式 → 确定 B 阶段可行性（半天内能给出结论）。
  • 挑 ArcReel 读它的分镜数据结构 → 决定 Skein 分镜表字段怎么定。
  • 看 video-recap-skills 的"导出剪映草稿"实现 → 验证「分镜表 → 草稿」这条链真的通。

如果这三条里有你想先确认的，说一声，我去把那个仓库读透再给你结论（而不是停在星数上）。
