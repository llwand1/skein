一句话

从这颗球开始做——但球是皮，骨头在下面。
Skein 是一颗常驻角落的球 + 一套不预设数量的叙事骨架。
它只做三件事：把"还差哪一段没站住"钉在你眼前；让你顺手把看到的喂进去；攒到差不多时提醒你可以发了——而"够不够"永远由你点。

名字：Skein

为什么是它
Skein
/skeɪn/ · n. 一绞线；线团
单根线没用，绕成一绞才有形——这正是本产品干的事：把散落的素材绕成一股叙事。
英语里它还有第二个意思：一群飞鸟。同一个词兼有"聚集"与"成形"，语源干净、冷门、独占性强。
内部仓库名继续用 task-orb，零成本。

五条思路

开工前必须先说清的决定
IDEA 01

"从球开始" ≠ "只做球"

球是载体，核心是骨架。只画一颗空球，什么都验证不了。
所以 M0 ＝ 球壳 + 一根最小骨头：球上要真的能显示"这期还差几段"、能点开看骨架。

IDEA 02

顺序改了，要留痕

之前拍的是「工作流先行、球后置」，现在改成「原生从球开始」——这是推翻。
会追加 P-011 记录本次拍板，并改写 requirements §2.2。

IDEA 03

栈复用词镜那套

Python 3.11 + Tk + pywin32/uiautomation，采集沿用 UIA 主 + 区域 OCR 兜底。
理由：它是本机唯一有完整交付记录（198/63 断言）的 Windows 桌面组合，不另起炉灶。

IDEA 04

最大风险先探

球要"置顶且不抢焦点"。Windows 上"显示即抢焦点"测不出来，真正分歧在鼠标点击。
所以 M0 自带探针，失败判据：球显示/点击后，浏览器光标与选区是否还在。

IDEA 05

红线不动

代码里不存在通往"发送"的路径，只有通往"打开页面"的路径。
微信个人号、抖音私信一律不引入（依赖就不引入）。

IDEA 06

完成度永不给 100%

系统只给估算（封顶 92%），最后一格由你点"够了，收口"。
宣布"完成了"的权力永远在人——这条从第一行代码就要落在数据模型里。

一次澄清：为什么"从球开始"依然合理

之前反对"先做球"，理由是球验不了闭环价值。但现在情况不同：交互叙事、素材入口、动态任务流已经在 demo 里跑通并被你认可了，闭环的"长什么样"已经不需要球去验。
此时从球开始，做的是把已验证的交互落地成原生，而不是"用球去猜产品"。前提是——球里必须真的连着核心（IDEA 01）。
仍然存在的代价：原生球一旦开工，就吃掉了"用土载体两三天跑完一期"的机会。
缓解办法：M0 的球只做壳 + 只读骨架，M1 立刻补最小核心；不要跳过 M1 直接做采集，否则会得到一个好看的、但没内容的球。

UIA TextPattern（不依赖焦点）区域 OCR 兜底

选型

M0 就要定的只有一对：主栈 + 球怎么实现
项选择理由 / 代价
主栈 Python 3.11 + pywin32 复用词镜交付（本机唯一有完整验证的桌面组合）。代价：工作台富交互弱，但 P0 不需要工作台。
球的实现 Tk Toplevel + overrideredirect(True) + -topmost + WS_EX_NOACTIVATE 不抢焦点的关键是 NOACTIVATE 扩展样式，不是 topmost。这条必须在 M0 用探针验。
数据 SQLite（本机已有） 关系型、单文件、零部署。词镜用 JSONL 是因为它记的是流式事件，场景不同，别照抄。
进程模型 采集常驻进程 + 球进程；SQLite + localhost 通信 采集端最容易崩，独立成进程 → 可单独重启/卸载。这条与选型无关，任何方案都成立。
暂不定 主栈之外的 UI 框架、多端、平台适配层 栈是定位的函数；"多平台"当前只是 Topic 上的一个字符串字段，不抽抽象层。

M0：球壳 + 探针

目标只有一个 —— 先证明"这颗球能安静地待在角落，不打扰你正在做的事"。
  1. 置顶且不激活的小窗无边框（overrideredirect）+ 置顶 + WS_EX_NOACTIVATE + WS_EX_TOOLWINDOW（不进 Alt+Tab）。
  2. 两种态 + 一个角标空态＝虚线圈 + "+"；有骨架＝进度环 + "≈62%" + 未站住数角标。数据先用假数据。
  3. 只读面板点球展开：Payoff / 覆盖图 / 节拍列表 / 蓝色"下一步"卡 / 估算条 + 封顶按钮。全部只读，不落库。
  4. 不抢焦点探针（关键）内置一条命令：记录球出现前/后的前台窗口与光标位置；点击球后再记录一次。
  5. 失败判据写死"显示或点击球之后，浏览器里正在输入的输入框是否仍可继续输入、选区是否仍在" —— 答否即 M0 不过。

M0 的验收判据

判据怎么验
不抢焦点（硬）打开浏览器在输入框打字途中，球出现／点球 → 光标与选区是否还在。答否＝不过。
不烦人（软）连续两天愿意让它开着 —— 这是"轻"的唯一实证。
看得懂（软）任何时刻，球和面板能替你说出"我在干什么 / 还差什么 / 下一步"。
别把这条当形式：Windows 上"显示即抢焦点"这个失败模式根本测不出来——所以探针必须测点击，而不是只看球冒出来。

M0 明确不做

  • 不接采集（UIA / OCR）——那时 M2 的活
  • 不接 LLM——假数据够用
  • 不落库——M1 才建表
  • 不做工作台窗口——球上的面板就是 P0 的全部界面
一句话：M0 只回答"球能不能安静地存在"这一个问题。
