核心动作没变，还是「喂」；变的是它能接什么

上一版把「喂」做窄了，等于"划选文字"。这一版补齐：一个动词，四种物料，多个入口。
喂 ＝ 把眼前的东西交给这一期缺的那一项。
眼前的东西可以是：一段文字、一张图、一段视频（带时间点）、或者你自己打的一句话。
关键升级：勾 = 有素材。你不能再空手打勾——没喂过东西的那一项就是"待喂"状态。清单从此是一排等被喂的槽位，不是一张要你划勾的待办。

四种物料 × 各自入口 × 喂下去存什么

物料入口（怎么拿到）喂下去存什么没有它就会缺什么
文字网页里划选一段 / 复制后粘贴原文 + 来源 URL + 时间最基础的"可回源证据"
图片悬停图片出现"喂这张图" / 截图 / 粘贴图片本体 + 来源 + 时间封面、对照图、教程截图
视频悬停视频出现"喂这段视频" / 粘链接链接 + 时间点(如 02:13) + 封面"看哪一段"的定位；否则素材等于没有
速记自由输入框 / 全局快捷键（demo 按 F）你自己打的话（无来源也算数）你在没网页可划选时闪过的想法

自由输入的入口在哪 —— 三个，覆盖三种场景

入口触发方式什么时候用
1 · 球面板底部输入框点球 → 面板底部常驻输入区你正在看清单，突然想到一句要补进去
2 · 全局快捷键任何软件里按 F（真实产品里是可配置的全局热键）不离开当前界面就能记一句——这是"边工作边顺手记"的正解
3 · 划选浮层里的输入框划选后，在浮层里补一句自己的话既要原文，又想附上"我为什么觉得它有用"
三者共用同一个"喂"的下游（选目标项 → 存素材 → 推进进度），所以不增加学习成本——只有入口多，动作仍是一个。

兜底：暂时不知道该喂给哪一项怎么办

  • 喂的菜单里永远有最后一项：「先存本期，稍后归类」。
  • 它进"本期暂存区"，不占进度；等你回看清单时再拖/点到具体项。
  • 这条同时解决了 requirements §2.3 记的那类摩擦——"看到了但没喂"里，"不知道该喂给哪一项"从此有地方可放，不会被丢掉。

关于 MCP，真正新的那一点在哪

很多人第一次看 MCP，会把它理解成"又一种函数调用"。这个理解不算错，但它解释不了一个事实：为什么大家已经能用 function calling 把模型接到自己的数据库上了，还非要再套一层协议。

图 · 协议分层示意图（演示占位图）

真正的差别在于：协议把"发现能力"和"使用能力"这两件事标准化了。工具清单可以被询问、可以被列举、带着输入模式返回；宿主不必在编译期就知道世界上有哪些工具。

官方讲解录像（演示占位） 02:13

反过来看边界也清楚：它不负责模型好不好、不负责推理质量、也不替你做权限判断。把它当万能钥匙会失望，把它当"集成层的最小公约数"则刚好。

为什么不做成"万能收集箱"

  • 万物皆可喂，但喂的落点永远是"这一期缺的那一项"——不是无限仓库。这挡住了它退化成又一个稍后读工具。
  • 速记不强制选项：不确定就先暂存。但它不占进度，避免"存了一堆没归类"造成虚假的完成感。
  • 视频必须带时间点：因为 P0 的验收是"攒齐的素材能直接进排版"，只给一条链接等于没给。
