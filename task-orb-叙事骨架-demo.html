关于 MCP，真正新的那一点在哪

很多人第一次看 MCP，会把它理解成"又一种函数调用"。这个理解不算错，但它解释不了一个事实：为什么大家已经能用 function calling 把模型接到自己的数据库上了，还非要再套一层协议。

图 · 协议分层示意图（演示占位图）

真正的差别在于：协议把"发现能力"和"使用能力"这两件事标准化了。工具清单可以被询问、可以被列举、带着输入模式返回；宿主不必在编译期就知道世界上有哪些工具。

补上的那一段：主题之前

上一版直接从"定这一期"开始，把前面最关键的一步丢了：你常常还没有主题，就已经在随手记东西了。
所以完整链路是：灵感池（还没主题，先收着）→ 立项（定这一期讲什么）→ 骨架 → 喂素材 → 饱和 → 发布。
依据：P-002 原话"随手记下一些素材，然后一步步去形成一篇独创的文章"。

四个阶段

阶段球的状态你做什么出口
1 灵感池空球（虚线圈 + "+"），不占用注意力看到什么都先收着；无来源也算数灵感池有货
2 立项球开始有内容（覆盖图出现）从排期挑一期，或"用灵感池起一期"骨架生成，灵感素材一并带入
3 喂素材球显示"还有 N 段没站住"划选/图片/视频/速记 → 支撑某一段每段被支撑且被确认
4 饱和发布球变色脉冲"这段讲清了"看草稿、跳发布页，自己发真发出去

为什么"灵感池"这一层不能省

  • 没有它，"顺手记"就没有落点。你看到好素材的那一刻，往往并没有在做的主题——如果产品此时要求"先定主题"，就等于逼你当场做决策，直接违背 P-007 的"轻"。
  • 它是选题的来源。排期表是"计划内"，灵感池是"计划外"——很多期就是从池子里某几条素材"攒出来"的（对应 P-002）。
  • 它把"框住"和"随手"分开。灵感池不占任何主题的进度，避免"存了一堆没归类"造成虚假完成感。

叙事骨架与饱和（承接 v0.2 模型）

Payoff这一期最想让人记住的那一下1
节拍用"必须回答的问题"表述不固定（建议 4~7）
素材挂在节拍下的证据（文字/图片/视频/速记）不预设，0~N
三方分工：系统报状态（红/黄/绿 + 冗余提示）｜AI 提缺口、一次只问一个｜人终裁"够了，这段讲清了"。铁律：AI 与系统只能提示"还没饱和"，宣布"讲清了"的权力永远在人。
饱和两条判据：覆盖（每段至少 1 条）＋ 解释力充分（新素材不再改变这段的讲法，且人确认）。研究原话：质量（充分）而非数量（多少）是饱和的关键。
