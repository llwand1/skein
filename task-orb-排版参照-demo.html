一句话结论

下面四套都拿同一份真实内容渲染：这一期 E005《MCP 到底创新在哪》+ 4 个素材项 + 进度 2/4。你直接比对哪套"一眼就会用"。
骨架抄滴答清单（TickTick）的三栏：期列表 → 素材清单 → 详情。素材卡样式补抄 Cubox（原文摘录 + 来源 + 时间）。理由：P0 的屏就是"清单主线 + 每项背后挂一段素材原文"，TickTick 强在清单主线、弱在素材长什么样，Cubox 正好反过来，两者拼起来没有缺口。

四套候选横评

候选骨架与 P0 的贴合主要代价
A · TickTick 三栏清单分类 / 任务列表 / 任务详情最贴合 三栏一比一对应"哪一期 / 素材项 / 素材原文"素材卡样式要自己补，详情区偏"任务"，不是"素材"
B · TickTick+CuboxA 的骨架 + 素材卡样式来自 Cubox最贴合 骨架和素材表达都补齐两套视觉要统一成一套 token，前期多花一点
C · Notion 式数据库表视图 + 页面详情（block）通用但偏重 多期一览最好看，但还是"要主动打开"的气质一旦做多视图/无限嵌套就膨胀，违背 P-007「轻」
D · Todoist 极简两栏：清单 + 极简详情不够用 没有素材原文/来源的落点P1/P2 必然返工
判据：P0 的"素材原文 + 来源"必须能在同一屏里读到 —— 这一条直接淘汰 D，也让 C 显得多余。
推荐：B（TickTick 骨架 + Cubox 素材卡）骨架能装下清单，素材卡能装下原文/来源/时间，且两者都是"轻"的工具，和你否掉的方向不冲突。
退而求其次：A如果嫌两套视觉要统一太麻烦，单用 TickTick 也能跑通，只是素材区会更像"任务备注"。
明确不推荐：C / DC 会把你往"重"带，D 撑不到 P1。两者都留作参考，不作 P0 骨架。

备注（TickTick 详情区原生支持）：封面大字候选「它不是替代品。」

就地讲解

1抄：左栏只放"期"。一期一行，行内带状态 + 进度（2/4）。这就是 P0 的 Topic 列表，栏位不用再发明。
2抄：中栏＝素材清单，复选框贴最左。名称加粗、提示灰字小一号 —— 层级就够用了，别加优先级/日期/四象限这些通用任务字段。
3抄：右栏＝详情，且必须同屏。TickTick 的"点一项就在右侧看详情、不跳页"正好接住 P0 的"勾一项 = 顺手喂一段素材"。
!不抄：优先级、日期/重复、日历视图、四象限、番茄钟 —— 全是通用任务管理，与本项目无关，抄进来就是学习成本（P-007 反对的正是这个）。
!风险：TickTick 的详情区本质是"任务备注"，宽度偏窄；而 P0 要在这里读"素材原文"，需要更宽的右栏。→ 所以右栏权重调大，或素材卡单独成块（见 B）。
适合度：★★★★☆骨架几乎零改动可用，只差"素材表达"这一块。
抄它的理由：中文原生、Windows 有客户端、学习成本低，气质与「轻」同频。

B · TickTick 骨架 + Cubox 素材卡（推荐）

就地讲解

1抄（TickTick）：三栏骨架、点谁看谁、进度条 + 2/4 的手感 —— 一个字不改。
2抄（Cubox）：素材卡＝摘录块 + 来源 chip + 采集时间。Cubox 的核心美感就是"原文是可回源的、带时间戳的一段"，这正是 P0「没有原文的打勾等于没打」的直观呈现。
3抄（TickTick 的详情位置）：把"草稿建议 + 跳发布页"放右栏底部。清单齐了这里才点亮 —— 与你 demo v0.4 里球面板的逻辑一致，将来球接进来只是换了个订阅者。
!不抄（Cubox）：它的"收藏流 / 标签树 / 稍后读"——那是素材为主的形态，本项目是清单为主，别把方向做反。
!风险：两套参照的圆角/间距/字号要收敛成一套 token，否则会"像两个软件拼在一起"。收敛规则：栏位间距跟 TickTick、卡片样式跟 Cubox、强调色用奶蛙黄 #FFD01F。
适合度：★★★★★清单主线与素材表达都补齐，且都属"轻"的工具。
代价：前期要把两套视觉统一成一套 token，一次性成本。

就地讲解

1值得抄的只有一处：数据库表视图。当你有 24 期排期时，"多期一览 + 状态/进度"这一屏确实比纯列表清楚 —— 这一块可以在 P1 之后补进来。
2block 混排：清单项与素材混在一起，好看，但"哪几项没做完"不如 A/B 的复选框列表一眼看清 —— P0 主线是"还差哪几项"，视觉上不该被素材块稀释。
!不抄：无限嵌套、slash 命令、多视图（表/看板/画廊）切换、属性面板 —— 每一样都是学习成本，正是 P-007 那句"一看就觉得有学习成本"的成因。
!风险：Notion 的吸引力在"什么都能做"，而本项目要的是"只能做这一件事"。抄它很容易把 P0 做成一个半成品 Notion → 白写率飙升。
适合度：★★★☆☆只借"数据库表视图"用于多期一览，不作 P0 主骨架。
结论：留作 P1+ 的"期总览"参考，不进 P0。

用途：反向标杆 —— 界面"热闹度"不得低于它、也不该远超它。
